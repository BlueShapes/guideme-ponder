# MOD解説ガイドの制作ノート

シリーズ全体の要件は [Ponderシリーズ共通制作方針](../../docs/mod-guide-authoring.md) を参照してください。
全8件に22言語対応を適用します。この文書には、AE2固有の実装例と制作・検証の記録を残しています。

更新日: 2026-10-23

AE2 Ponder Guideの制作中に確認した指示・修正履歴・実装上の知見を、別MOD向けの解説MODでも参照できるようにまとめた文書です。開発者向けの日本語資料であり、ゲーム内の教材・翻訳データとは別に管理します。

口調や翻訳の扱いは、利用者の明示的な指示と[このプロジェクトのAGENTS.md](../AGENTS.md)を基準にしています。実装の推奨事項は、現在のコードと検証で得た知見です。新しいプロジェクトでは、そのプロジェクトの指示・対象MODの仕様を優先してください。

## 1. 別MODへ引き継ぐ基本方針

- 内容に合った説明手段を選びます。短文で伝わるものはアイテム説明で完結させ、配置・操作・変化を見せる必要があるものはPonderで示します。
- Create/Ponderの口調と操作感に合わせます。標準の再生・一時停止・キーフレーム・前後移動・戻る操作を活用します。
- 教材の定義を中心に置き、字幕・一覧・検索・アイテムへの登録・ガイドページで同じ内容を使います。
- 対象MOD固有の模型・教材と、再生・検索・翻訳・ローダーの仕組みを分けます。
- 任意アドオンは未導入でも動く構成を保ち、導入されていない内容は入口・本文・検索のすべてから除外します。
- 実ワールドを変更せず、Ponderの仮想ワールドで説明用の模型を動かします。

今回の方針は「解説MODを別々に作る」場合にも使えます。最初から共通ライブラリ化する必要はありません。同じ仕組みが複数の解説MODで必要になった段階で、実際の共通部分を抽出するのが推奨です。

## 2. 口調・用語・文章の書き方

### 日本語

説明文は「です・ます」調を保ち、模型の操作・仕組み・条件と結果を説明します。操作のたびに「〜してください」と視聴者へ催促する形にはしません。「接続すると〜へ送られます」「この操作で〜を切り替えられます」など、表示している動作に合う文を選びます。確認・注意・対処を促す必要があるときは「接続を確認してください」等を残せます。タイトルや短いボタン名は、自然な名詞・短い動作名で構いません。短くするために説明文まで常体へ崩すことは避けます。

| 用途 | 推奨する書き方の例 | 避けたい書き方の例 |
| --- | --- | --- |
| 仕組みの説明 | ケーブルで装置を接続します | ケーブルで装置を接続する |
| 通常操作の説明 | ドライブに入れたセルが品物を保存します | セルを入れてください、次に端末を置いてください |
| 必要な確認・対処 | 動かない場合は接続を確認してください | 接続を確認しろ |
| 条件付きの説明 | 電力が供給されると、端末を利用できます | これで必ず使えます |
| タイトル | 最初のネットワーク | 最初のネットワークを作ってみましょう！！ |
| 短い操作ラベル | 次へ／戻る／検索 | 次に進んでください／前の画面に戻ってください |

上の文は書き方の例です。実際の装置名・成立条件は対象MODの仕様に合わせてください。ゲーム内の独自解説は全22言語で文末の句点・ピリオドを付けません。読点、小数・版番号・略語・ID・URL等に必要な点、継続の「…」は保持します。制作ノート等の開発文書は通常の句読点で記述します。

語尾を一括で置換したり、すべてを「〜できます」にしたりするだけでは自然な解説になりません。短い完結文を基本に、長い条件と結果だけを意味の切れ目で明示継続します。全22言語で操作対象・条件・数値・因果関係を確認し、他言語を日本語の語尾へ機械的に合わせません。命令形の件数は調査の手掛かりとし、通常操作・条件と結果・警告・対処の実例で推敲結果を評価します。

説明調への変更では、設定の選択肢を固定動作として書かないようにします。「信号があるときだけ動く設定にできます」と「信号があるときだけ動きます」は異なります。また、「同じプロバイダーへ結果を戻す必要があります」を「結果が戻ります」に替えると、必要な配線条件が自動動作の保証へ変わります。しきい値の数値と比較モード、DISK本体とその内容物、面を区別するかどうかの切替も、それぞれ区別して翻訳レビューします。

- 装置・アイテム・機能名は、対象MODのその言語での正式な呼び方に揃えます。
- 初出の用語は役割や見た目と結び付けて説明します。略語だけで操作を進めないようにします。
- 主語・対象を省略しすぎず、「これ」「それ」がどの模型を指すかを明確にします。
- 操作の理由や結果を添えます。長い文章になる場合は、場面を分けて示します。
- 数値・単位・上限・前提条件を残します。翻訳や短文化の過程で条件を落とさないようにします。
- 字幕は原則として短く完結した1文を1吹き出しにし、自然な折り返し後で最大3行・できれば2行にします。長い説明は、対象・条件・数値・因果関係を保持して原文と全22言語を推敲します。複数文が収まっても自動で同じ吹き出しへまとめません。
- 各ステップの`text.ja`・`text.en`と他言語の同じ字幕キーでは、作者が選んだ表示単位の間にJSONの`\n`を置きます。[CaptionPages](../src/main/java/dev/ae2guide/client/CaptionPages.java)はこの明示境界だけを読みます。文字数・単語・行数・フォント幅・句読点から境界を推測せず、未知の長文も途中で切断・省略しません。長すぎる単位は制作時の検査で修正対象にします。
- 短文に直しても一文のまま続ける必然性がある場合だけ、自然な節で`前半…\n…後半`のように継続を明記できます。3段なら中間は両端に`…`を付けます。単なる句読点の`…`を自動分割の合図にはしません。対応する前後の記号、順序、内容の保持も検査します。通常の短文に記号を追加する必要はありません。
- 説明字幕は標準の180px幅を確保し、対象模型は輪郭とアイテム吹き出しで結び付けます。Ponder 1.0.87の既定の`independent()`配置では最小GUI 320×240の実幅が118〜119pxに狭まるため、AE2ガイドだけを`independent(138).placeNearTarget()`へ置き、画面右側に余白を残すようX座標を補正します。タイトルや下部操作からも離します。字幕の内容を変える前に、実際の本文幅と配置を確認してください。別版へ移す際も同じ確認が必要です。
- 翻訳済みの表示単位をPonderの`.text(String)`へ渡すと、新しい連番の翻訳キーとして扱われます。専用sharedキーの`%s`へ引数で渡し、全文キーを原文・検索のために維持します。各単位には最低80 tickと文字量に応じた読む時間を確保し、前の字幕の消失後に次を表示します。検索用には表示境界を空白へ戻し、対応した継続記号だけを取り除きます。
- バージョンや設定で変わる仕様を断定しません。複数版で同じ仕様なら共通の表現を使い、異なる場合は対象版を示します。
- MODパックでレシピや設定が変更される場合は、その環境の設定を優先する旨を説明します。

### 完結した字幕単位の例

`first_network`の最初のステップは、セルを入れる操作・保存先・ドライブとの違いを、次の3つの完結文として順に表示します。`\n`は画面内の折り返しではなく、作者が指定した吹き出しの切り替えです。

```json
{
  "ja": "ドライブにストレージセルを入れます\n品物はセルに保存されます\nドライブ本体に保存されるわけではありません",
  "en": "Storage cells fit in an ME drive\nItems are saved in the cells\nThe drive itself does not store items"
}
```

`omni_cells`の容量計算も、「種類ごとの追加バイト消費はありません」→「アイテム8個で1バイトを使います」→「液体も8000 mBで1バイトを使います」→「両者で同じセル容量を共有します」へ分けました。対象・数値・容量共有の条件を保持し、どの吹き出しにも未完の断片を残していません。`things_disks`では、1アイテム当たり1バイトと、1k〜256kの各容量の具体値を、それぞれ完結文で伝えます。

継続表現は[共通要件67](../../docs/mod-guide-authoring.md#r067)の限定的な選択肢です。例えば`電力が不足すると…\n…接続した装置が停止します`のように、自然な条件節と結果節を作者が選びます。3段継続の中間には両端の記号が必要です。これは形式の説明例であり、今回の教材へ不要な継続記号を加える指示ではありません。略語・小数・版番号・レジストリIDや、文中の単なる`…`から境界を推測しません。

`python tools/captions.py check-all-locales`は、空の単位・複数文の結合・不要な文末句点・継続記号の対応などを検査します。英日で明らかな途中切断も検出しますが、文法や意味を完全に判定するものではありません。各言語の原文・訳文の編集レビューと、実フォントでの3行制限の確認を併用してください。

### 英語・その他の言語

各言語でもCreate/Ponderの自然な説明・呼びかけに合わせます。日本語の丁寧さを、そのまま全言語の敬語へ置き換える方針ではありません。

- チェコ語は丁寧な複数形、欧州ポルトガル語はtuなど、その言語で指定された呼びかけ方を守ります。
- 香港・台湾の繁体字中国語、ブラジル・ポルトガルのポルトガル語は別々に確認します。
- 固有名詞、数値、プレースホルダ、アイテムの同一性、成立条件を保存します。
- 命令を強めたり、原文にない保証・機能・条件を追加したりしません。

口調の修正例は、コミット `da2b0d8`（`fix: align guide translations with Create tone`）と現在の[原文](../src/main/resources/assets/ae2ponder/guide/lessons.json)・[各言語の翻訳](../src/main/translations)で確認できます。

### 表示単位の意味に合わせた文字色

通常の事実・基本手順は白、警告・失敗条件・損失リスクは薄い赤、任意の工夫・対処や診断の助言は薄い緑にします。Ponder本文は`CaptionTone`の`NORMAL`・`WARNING`・`HINT`を、それぞれ標準の`PonderPalette.WHITE`・`RED`・`GREEN`へ対応させます。標準描画が明るい本文色へ変換します。模型の輪郭の色は別の目的なので、本文の分類から変更しません。

[caption_styles](../src/main/caption_styles)に各言語の字幕キーと役割の配列を置きます。配列はその言語で作者が指定したLF単位と一対一です。英語と異なる分割数の訳文へ英語の番号を流用せず、各部分の意味を確認します。例えば`certus_growth_4`の「修復の限界」「完全な母岩の成長」「移動の助言」は警告・通常・ヒントです。ステップ全体の`warning`は輪郭用に残し、本文色には使いません。

`_caption_hash`は言語と字幕の全文・キーに結び付けたレビュー記録です。`python tools/caption_styles.py`と翻訳検査・Gradle生成で、22言語の存在、キー、単位数、役割、ハッシュを検査します。字幕を変更したら各言語の意味と役割の対応を確認してから更新します。単語検索や実行時の自動分類では代用しません。

アイテム説明の事実は通常色、展開キーの任意ヒントはヒント色です。独自ME Guideページの説明・要約は標準`Color`タグで通常色を指定し、リンク・見出し・他MODやGuideME標準UIの色は維持します。Ponder外の本文も、標準本文と同じ`0xffffdd`への0.5の混色を使います。

## 3. レッスンと演出の組み立て方

### 最初に、テキスト説明とPonderを使い分ける

「全アイテムにPonderを付ける」ことは目標にしません。利用者から追加された、Createの装飾品のようにアイテムのテキストだけで説明を完結させる方針も引き継ぎます。説明の量やレッスン数より、そのアイテムを理解するのに必要な情報を優先します。

| 説明手段 | 選ぶ基準 | このプロジェクトの例 |
| --- | --- | --- |
| アイテムの短い説明だけ | 役割や注意点が短文で伝わり、配置・動作の実演を必要としない | 装飾用Certusのブロック・階段・壁・ハーフ、ケーブルを覆うファサード |
| Ponder | 接続面、入出力、順序、状態の前後などを見比べると理解しやすい | ネットワーク、加工・自動クラフトなどの構成 |
| 短い説明とPonderの併用 | アイテムの役割は短く伝えられるが、使い方に空間的な条件がある | ケーブルアンカーの接続遮断 |

ケーブルアンカーは装飾にも使えますが、取り付けた面の接続を遮断する機能があります。装飾専用とは説明せず、アイテム説明には接続遮断と側面をはしごとして使えることを書き、既存の配線レッスンで同色ケーブルの接続前後を見せます。ファサードはケーブルや面パーツの接続を保ったまま外観を覆うため、この違いも短文で伝えます。

「見た目が装飾ブロックに似ている」だけで分類しません。たとえば通常のCertus Quartz Blockは素材・結晶の圧縮保管にも使われるため、今回の装飾用グループには含めません。対象版の公式ガイド・レシピ・実装を確認し、グループに入れるレジストリIDを明示します。

短文だけの対象を無関係な場面へ登録したり、説明文を読むだけの空のレッスンを作ったりしないようにします。テキストだけの項目はアイテムから読み、Ponderの一覧・コース・学習進捗にはレッスンだけを載せます。既存の場面を削る場合は、そのアイテムに関連する本来の機能説明まで失わないかも確認してください。

### アイテム説明の実装と文章

- 役割と必要な条件を短く書きます。アイテム名やレシピ一覧の繰り返しで説明欄を埋めず、既存の対象MODの説明も確認します。
- この実装では、対象アイテムでShiftを押すと本文を表示します。通常時は短いヒントを表示し、対象MODや他MODの既存ツールチップを保持します。Ponderがあるアイテムでは標準のPonder導線と併用します。
- 名前・対象ID・本文の定義をデータとして管理し、ローダー固有部分はイベントの接続だけにします。既存のイベントAPIで実装できる場合は、共通の描画処理にMixinを追加する必要はありません。
- 文字数だけで折り返し位置を決めず、選択言語のフォント幅と画面幅を考慮します。本文を英語でキャッシュせず、言語変更後も選択言語で展開します。
- 任意アドオンの短文にも`requiresMods`を付け、未導入時はツールチップの入口から除外します。版に存在しないIDと未導入MODを区別し、同じ定義を両版で使う場合は実レジストリで対象を選びます。
- 一つの短文説明にも、完結した事実をLFで区切れます。`tones`を指定した説明は、その言語の各LF単位に通常・警告・助言の色を対応させます。折り返し後の3行制限は各単位へ適用し、複数の単位を持つツールチップ全体を途中で省略しません。
- 短い説明・展開ヒントも、このプロジェクトでは全22言語の原文ハッシュ・翻訳・描画確認の対象です。表示対象アイテムの存在、展開前後、他の説明の保持、テキスト専用品にPonder導線が出ないことを検証します。

### 元ガイドと実アイテムから入口を監査する

登録済みの教材だけを数えると、未登録の色違いや道具を発見できません。対象版のレジストリ初期化・実際の色ループ・元ガイドの関連IDから先に対象一覧を作り、その後でPonderとShiftの実登録を照合します。今回の独立した一覧と変更前後の対応は[item-coverage.json](item-coverage.json)、再検査は`python tools/item_coverage.py`です。

ケーブルは5種類×17色の85 IDを確認しました。同じ種類の色違いは、代表色だけでなく全17色で同じコースへ接続します。ガラス、被覆、スマート、被覆高密度、スマート高密度の間では、機能と学習順が異なるため、別のコースを保ちます。タグ画面の代表カードを絞る処理をW登録へ流用しません。

見た目だけで装飾専用と判断しない例には、結晶へ戻せるCertus Quartz Block、素材をまとめるOmniブロック、接続を遮断するアンカーがあります。短文には実際の機能を残し、必要な接続前後だけをPonderで示します。MEGA CellsとMEGA Things、資源セルとAE電力セル、クラフト用メモリー、通常セルと種類上限のないDISKも区別します。

チャージ済みのスタッフは充電・近接攻撃・放電の変化を専用教材で示します。固定した両版では蓄電量が厳密に300 AEを超えると放電し、300 AEを消費します。追加魔法攻撃の基本ダメージ6を、通常打撃を含む確定総ダメージとは記述しません。蓄電量のようなItemStackのデータは、教材の選択のために消去・正規化しません。

Ponder 1.0.87の`of(ItemStack)`はレジストリIDで教材をコンパイルし、表示対象をデータなしのスタックから作り直します。自ガイドの対象については元のスタックをコピーして保持し、履歴の同値判定でも全成分を比較します。表示のAE値だけでなく、空・300・1000 AEのWとカテゴリー往復で入力と表示対象の全成分を確認します。別アイテムの履歴や全教材コースまで一律に変更しません。

### レッスンを作る前に整理すること

1. このレッスンの到達点を一文で書きます。
2. 必要な知識・素材・装置と、その入手や準備を先に学べるレッスンを確認します。
3. 正常な使い方を示し、その後に制約・失敗条件・切り分け方を説明します。
4. 学習順を章・一覧・コースの順序で揃えます。関連アイテムからも同じ場面へ到達できるようにします。

AE2では、準備からネットワーク・収納・自動化・高度な構成・トラブルシューティングへ進む構成を採っています。別MODでは対象の学習順に合わせて章を設計し直してください。章名やレッスン数をそのまま引き継ぐ必要はありません。

### 一つのステップで伝えること

推奨する説明の単位は「対象を示す → 操作や変化を見せる → 結果・条件を説明する」です。字幕に書いた対象を輪郭や吹き出しでも示し、隠れている模型へ注目させないようにします。

- 収納セル、材料、カード、パターン、工具などは、アイテム画像付きの吹き出しで示します。
- 吹き出しは対象装置に結び付け、複数の材料は順番に表示します。
- 右クリック・左クリック・スクロール・スニークの印は、実際に必要な操作に使います。単なる材料紹介と操作指示を混同しません。
- 移動するアイテムや線は説明用の演出です。実際の処理速度・転送量を保証する見せ方は避けます。
- 字幕・吹き出し・模型の変化のタイミングを揃えます。読み終わる前に対象が消えないようにします。
- 読む時間は日本語・英語だけで固定せず、選択中の翻訳の長さも考慮します。一時停止やキーフレームも利用できるようにします。

現在の[GuideScenes](../src/main/java/dev/ae2guide/client/GuideScenes.java)は、各表示単位へ最低80 tickまたは文字数の2倍のtickを確保し、単位間に12 tickを加えます。Ponder 1.0.87は表示時間に前後5 tickずつのフェードを追加するため、その分を差し引いても2 tickの余裕を残します。実際の描画ではフェードの閾値も関わるため、ネイティブ再生で読む時間・消失・順序を確認します。ステップ全体では最低120 tick、アイテム吹き出し1個につき72 tick、原文・選択言語の文字量も下限に使います。各単位の長さに応じて間隔が変わり、複数文を同じ時間枠へ詰めません。これらはこの実装の調整値であり、別MODの教材で必ず同じ値を使うという要件ではありません。

現在の字幕キーにはステップの位置が含まれます。ステップを挿入・並べ替えた場合は、同じキーのまま内容が変わる可能性があります。後続の字幕も含め、全言語の対応関係を確認してください。レッスンIDの変更はコマンド・リンク・学習進捗にも影響します。

### 模型と対象MODの状態

- 必要最小限の共有ステージに、教材定義から模型を配置します。
- レジストリIDだけでなく、ステートの名前・値、部品ID、NBTの意味を対応版ごとに確認します。
- 対象MODが公式に提供するvisual NBTなどの表示用の仕組みがあれば、まずそれを利用します。AE2のvisual NBTを他MODにも存在する仕様として扱わないでください。
- 再生の最後だけでなく、巻き戻し・再生し直した後も部品が復元されることを確認します。
- ブロックエンティティが存在するだけでは、模型が見えている保証になりません。モデルデータ・描画面・実際の画像も確認します。

Ponderのステージは、構造NBTの`size`だけでは意図したワールド境界にならないことがありました。[generate_structure.py](../tools/generate_structure.py)では上部の空気ブロックを明示しています。共有ステージのDataVersionは、利用する内容が互換であることを確認して、最も古い対応版に合わせています。

## 5. UIとクライアント側の責務

### 標準操作を再利用する

このMODで採用した入口は、アイテム上でのWキー長押し、クライアントコマンド、ME Guideのリンクです。共通要件68に従い、設定画面を含む通常のMinecraft画面へ独自ボタンを追加せず、専用のPキー割り当ても設けません。Ponder内の標準タグボタンと再生操作は維持します。

- 章の入口は、登録済みの章タグを表示するPonder標準の`PonderTagIndexScreen`と`PonderTagScreen`です。共通要件40に合わせ、独自の章サイドバー・章フィルター・教材選択画面を廃止しました。標準タグ一覧は他MODのタグも表示し、AE2内ではタグ登録順を保ちます。
- `/ponder-ae2`（互換名`/ae2ponder`）は標準タグ一覧へ進みます。章番号・章名、`item <名前>`、既存の`lesson <ID>`からも教材を選べます。教材の題名・要約・字幕の検索は既存のGuideME標準検索を使います。
- 字幕は生成ページの`ae2ponder:SearchTerms`へ論理順の翻訳原文として渡し、GuideME標準の`TagCompiler.index`拡張点で索引に加えます。表示時はこのタグの本文を省き、既存の章・教材リンクの構成を保ちます。任意アドオンの字幕も同じ導入条件の内側に置き、不在時には索引へ入りません。
- GuideME 20.1.15・21.1.19では、検索語に英語のatやアラビア語のعندなどが含まれると、言語解析が返した空の句を検索条件へ追加して例外になる場合があります。`GuideSearchQueryMixin`はその空の句だけを一致しない句へ置き換え、残りの語で標準検索を続けます。元の呼び出しを残す`@ModifyArg`で補正し、同じ補正が重なっても非nullの句は変更しません。
- 標準タグ画面のアイテムから選んだ場面を、全コース内の開始位置として開きます。前後のレッスンへはPonder標準の左右操作で進めます。
- Ponder 1.0.87の標準アイテム選択は、そのアイテムの教材だけをコンパイルします。共通要件41の全教材コース内の開始位置を維持するため、この選択を既存の`GuidePonderScreen`へ接続します。追加の章一覧や再生操作は作らず、関連付けの登録順とPonderの履歴を利用する小さなアダプターに留めます。アイテム上のWは標準の関連教材コースを開きます。
- 戻る操作で、起点の一覧やガイド画面へ戻れるようにします。
- 全教材コースでは、選択教材のアイコンと章タグを開始時・前後移動後に同期します。通常の関連アイテムには実際の`components`のタグを登録し、標準Wコースを使います。全教材を持つME GuideアイテムのW起動だけは全教材アダプターへ接続します。未導入アドオンの代表アイコンを章に残さず、章内の選択で他章の教材へフォールバックしません。
- Ponder 1.0.87の`referredToByTag`は「その章の先頭へ移動する」一回限りの要求です。タグを表示するために設定すると、選んだ途中教材が次のtickで上書きされます。表示更新には`stack`と`tags`だけを使い、章が変わったときに`rebuildWidgets()`で標準ウィジェットを再構築します。再生位置を変える要求とは分けます。
- Catnipの戻る履歴は画面の`isEquivalentTo`を使います。標準Ponderはアイテム一致だけで同一と判断するため、全教材アダプターとは相互に区別します。アダプター同士はコンパイル言語と選択scene IDも比較します。先頭sceneが他MODに属するタグ起動前も区別し、通常のPonder画面同士の判断は変えません。
- Catnipの遷移アニメーションは、その仕組みに対応する画面同士で使います。通常のScreenからは`ScreenOpener.open`を利用し、対応画面間では`transitionTo`を使います。[GuidePonderScreen](../src/main/java/dev/ae2guide/client/GuidePonderScreen.java)が実例です。
- 関連アイテムの固定配置は避け、画面幅・高さに応じて列数や行数を決め、収まらない分はページに分けます。
- 既存の`PonderTagScreenMixin`はAE2タグだけの関連アイテム配置・ページ分割とコース開始の接続を担当します。独自の章編成画面を再配置したものではありません。模型・多言語描画・版互換の補正も、それぞれの目的と範囲を保ちます。
- ワールドのレジストリアクセスを必要とする処理は、タイトル画面の設定から実行させません。

### クライアントだけで完結させる

ガイド本体は、クライアント限定のイベント、クライアントコマンド、クライアント用Mixin、ローカルの学習進捗で構成します。実ワールドへの操作、独自通信、新規ブロック・アイテムの登録を必要とするかは慎重に判断してください。

「専用サーバーでクライアントのクラスをロードしないこと」と「サーバーへガイドMODを入れずに接続できること」は別の確認項目です。後者を保証する場合は、接続設定に加えて実接続を検証します。ガイド本体の条件と、対象MOD・アドオン自体の通常のサーバー導入要件も区別します。

このプロジェクトについて行われたクライアント側構成の確認は、静的な実装・設定の確認です。その確認だけを根拠に、ガイド未導入の専用サーバーへの実接続まで検証済みとは扱いません。

## 6. 多言語対応と文字描画

### 対応範囲と翻訳の管理

このプロジェクトの対応範囲は、[languages.json](../src/main/translations/languages.json)にある22言語です。字幕だけでなく、題名・要約・一覧・検索・章・Ponder/GuideMEの操作表示・ガイドページを同じ変更で更新します。

Ponderシリーズの全8プロジェクトは、利用者の2026-10-20の指示により、第一・第二言語範囲の全22言語に対応します。日英のみの実装から始めたプロジェクトにも適用する要件です。共通の対象は [languages.json](../../docs/languages.json)、制作方針は [共通文書](../../docs/mod-guide-authoring.md) にまとめ、各プロジェクトのAGENTS.mdにも明記します。

- 日英の原文と他言語の翻訳を分け、配布用の言語JSON・ページは生成します。生成物を手で直したり、別の原本を重複管理したりしません。
- 対応言語を英語フォールバックで済ませません。対象外ロケールや欠落時の最終フォールバックは英語とし、既定のME Guideページも英語にします。
- `%s`・`%d`などのプレースホルダ、数値、レジストリID、コマンドIDを保存します。
- `_source_hash`は原文変更を検出するために使います。変更された原文を各言語で確認してから更新します。検査を通すためだけの更新は行いません。
- 日英両方の確認も`source-review.json`に記録します。英語のみ、または日本語のみを変えて、もう片方を確認せず残さないようにします。

このリポジトリでの手順は次のとおりです。

```powershell
python tools/localization.py source
# 変更した原文を日英・全翻訳で確認し、翻訳とレビュー記録を更新する
python tools/localization.py check
python -m unittest discover -s tools -p test_localization.py
```

### 翻訳ファイルの存在だけで完了としない

- 検索は選択言語の題名・要約・字幕で試します。トルコ語のI/İなど、その言語の大小文字変換も確認します。
- アラビア語は、論理順の原文と描画用の整形結果を分けます。検索・コマンド・原文のASTを描画のために書き換えないようにします。
- 字幕の幅は、整形後に実際に描くグリフの幅で測ります。論理文字列の幅だけで折り返すと、枠からはみ出す場合があります。
- 一度整形した文字列を、さらに自動整形する描画経路へ渡さないようにします。
- ヒンディー語・中国語・韓国語・アラビア語なども実際に描画し、文字の欠落・字幕枠・長い操作ラベルを確認します。
- ロケールJSONの検証では、`getResourceOrThrow`で一つのファイルだけを読むと、依存MODの部分翻訳だけを取得する場合があります。ゲームの合成結果と比較するときは、`getResourceStack`をMinecraftと同じ順序で合成します。

実例は[RightToLeftText](../src/main/java/dev/ae2guide/client/RightToLeftText.java)、[GuideArabicTextMixin](../src/main/java/dev/ae2guide/mixin/GuideArabicTextMixin.java)、[GuideLanguageValidation](../src/validation/java/dev/ae2guide/validation/GuideLanguageValidation.java)です。

## 7. 任意アドオンを扱うとき

対応済みの4アドオンは、実名ごとの標準章・タグに分けます。章IDは`ae2omnicells`、`bigger_ae2`、`ae2things`、`ae2_mega_things`で、本体6章の後へこの順に並べます。導入されていない章は列挙しないため、コマンドの章番号は有効な章の順番から求めます。教材ID・アイテムの対応・各ステップの模型は維持します。複数のアドオンを一つの総称章へ集約したり、独自の章選択画面を増やしたりしません。

ME Guideでは各アドオンの見出し・説明・教材リンク・字幕の検索用本文まで、同じ導入条件の内側で生成します。見出しだけ残る空章、未導入教材の索引、別アドオンへ移る関連アイテムを作らないよう、16通りの有効教材・章・順序と実際の標準タグ導線を検査します。追加アドオンを採用するときは対象版・ローダーごとの実ファイルと必要依存を確認します。今回のAE2作業では新しいアドオンの追加を行わず、既存4件を対象にします。

表示条件は教材の`requiresMods`で管理し、その条件を一覧・Wキー候補・タグ・コース・ガイド本文・検索に一貫して反映します。ガイドページの見出しだけを隠して本文や索引を残す実装は避けます。

- 任意アドオンのJavaクラスを直接参照しません。MOD IDとレジストリIDを使い、読み込み・登録・描画の前に条件を評価します。
- 必須にしないアドオンは、配布メタデータでも任意扱いにし、JARへ同梱しません。
- 開発・検証の標準構成には対応アドオンとその必須依存を含め、別途アドオンなしでも確認します。
- 前提となる依存MODは、Minecraft版・ローダーごとに調べます。Forge版とNeoForge版で同じ依存関係とは限りません。
- 少数のアドオンなら、表示条件の組み合わせは純粋なフィルターの検査で網羅します。4アドオンの16通りを確認するために、16回Minecraftを起動する必要はありません。

本文と索引の条件分岐は[OptionalModTagCompiler](../src/main/java/dev/ae2guide/client/OptionalModTagCompiler.java)、導入状態の純粋な絞り込みは[GuideBook](../src/main/java/dev/ae2guide/client/GuideBook.java)が実例です。

## 8. バージョン・ローダーをまたぐ構成

教材・翻訳・共通の再生や検索を共用し、ローダー登録・イベント・版別APIを小さなアダプターへ分けます。このプロジェクトでは`src/main/java`を共通部、`src/forge/java`と`src/neoforge/java`を版別部にしています。検証も同じ分け方です。

移植では、まず依存MODの実際の対応版とAPIを確認します。似たクラス名や新しい版の資料だけを根拠に置き換えないようにします。

| 確認する差分 | 今回の具体例 |
| --- | --- |
| Javaの対応範囲 | Forge 1.20.1はJava 17、NeoForge 1.21.1はJava 21。共通処理ではJava 21専用のList APIを避ける |
| MinecraftのAPI | ResourceLocationの生成、OptionsScreenの場所、スクロールの引数、NBT保存、ワールド生成 |
| ローダーのAPI | イベント・MOD一覧・設定ディレクトリ・描画用モデルデータ |
| 依存ライブラリの挙動 | Forge側Ponderはブロックエンティティからモデルデータを取得するため、NeoForge用の補正Mixinをそのまま追加する必要はなかった |
| 配布時の名前変換 | Forgeの再難読化とrefmap。開発環境で動く名前が、そのまま配布環境に存在するとは限らない |
| リソースのメタデータ | `pack.mcmeta`を用意し、対象版のリソース・データパックの形式に合わせる |

Mixinでは、独自ライブラリのメソッドと、その中で呼ぶMinecraftメソッドを区別します。外側のMixinが`remap=false`でも、Minecraftの呼び出し先には再マッピングが必要な場合があります。継承した`Screen.init`のようなメソッドも対象です。今回のForge版では、refmapに`init → m_7856_`と字幕描画の呼び出し先が含まれることを確認しています。

字幕のX補正は、Ponderが計算した値を受け取る`@ModifyVariable`を使います。元の`Math.min`呼び出しを残し、他のラッパーや同種の補正と連結できる形にします。対象は`ae2ponder`の場面だけです。Ponder 1.0.87の両対応版で、最初の`Math.min(float,float)`直後のfloatローカル11が対象X、その後の同じ呼び出しが本文幅`min(画面幅 − X, 180)`を計算することを確認しました。注入範囲と件数を限定し、別の検証用補正も同じ箇所へ適用します。RTLの折り返し・計測補正は維持します。版更新ではこのローカル配置と呼び出し順を再確認してください。

配布JARの確認には、正しいローダーのメタデータ、対象Javaのクラスバージョン、refmap、ライセンス、対応言語を含めます。検証用クラスや依存MOD本体が紛れ込んでいないことも確認します。版ごとのビルド出力・開発ワールドを分け、古い版で新しい版のワールドを開かないようにします。

別MODでも共用率の数値自体を目標にせず、意味が同じ教材と処理を共用し、仕様の違う部分を明示することを優先してください。

## 9. 検証を安く、確実に進める

### 確認する順序

1. 原文・レジストリID・依存関係・変更箇所を調べます。
2. コンパイル、教材生成、翻訳の整合性検査など、小さく安い確認を先に行います。
3. データの絞り込みや翻訳検査は、可能な範囲でゲームを起動せず確認します。
4. 描画、画面遷移、巻き戻し、実際の言語検索は、必要な構成の非表示クライアントで確認します。

## 10. 再利用・配布時に引き継ぐもの

- 共通の実装を別MODへ持ち出す場合も、Javaパッケージ、名前空間、MOD ID、翻訳キー、コマンド、進捗ファイル名を独立させます。Mixin設定・refmapのファイル名、その設定への参照も揃えて変更します。識別子・クラス・保存先の衝突を防いだうえで、同時導入時の挙動を確認します。
- 名前を分離しても、同じ依存MODへ適用するMixinは競合する場合があります。Ponderの同じ字幕描画処理を複数の`@Redirect`で置換すると、処理内に名前空間判定があっても注入先が競合します。`PonderTextWindowMixin`は元の呼び出しを残す`@ModifyArg`・`@ModifyVariable`へ変更しました。引数全体を受け取る`@ModifyArg`を使い、Forgeのモジュールローダーで読み込めなかった`@ModifyArgs`の生成クラスも避けています。対象版でローカル変数の配置も確認し、更新時には再確認します。
- PonderやGuideME全体へ適用する補正は、元の解説MODと新しい解説MODを同時に入れて検証します。競合する補正は共通の依存ライブラリで一度だけ適用する、または共存できる注入方式へ設計し直すなどの対応が必要です。教材・登録処理の再利用と、グローバルなMixinの複製は分けて判断してください。
- 対象MODの全アイテムや仕様をそのまま流用せず、新しい対象のレジストリID・説明・状態表示を改めて確認します。
- 利用したコード・UI文言・翻訳の出典とライセンスを記録します。AI経由で生成・翻訳したことを、元の権利表示を省く理由にはしません。
- Ponder由来のコード・UI文言にはMITの権利表示を保持します。このプロジェクトのGuideME由来のUI文言・翻訳はCC BY 4.0として管理し、独自部分のMITと区別します。
- GuideME本体のコードは、別途導入するLGPLv3の依存ライブラリとして扱っています。ソースや改変コードを新たに取り込む場合は、その利用形態に応じた条件を確認します。
- JARには必要なライセンス本文と出典文書を含め、依存MODのJAR・画像・モデルを不用意に同梱しないようにします。
